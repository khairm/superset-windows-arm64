**What changed**
1. **Two lanes.** GitHub calls (`gh/exec`) get their own 6-slot pool. Git and token lookups keep a 4-slot pool, so a sweep's GitHub burst can't hold up a Changes read.
2. **Bounded queues.** Reads wait at most 5 s in the git lane and 30 s in the GitHub lane. Caps are 32 and 64 queued reads. Expired or over-cap reads are rejected before they start, with no `killed`/`signal`, so they don't trigger a GitHub hold. Mutations are never dropped, merged or retried.
3. **Refuse mode for all git/gh work.** This now includes the existing shared-pool git tasks (commit, push, removeWorktree and others). There is no inline retry and no main-thread fallback. Usage tasks keep today's behaviour. Two more safety pieces:
   - The worker must report its task list at startup, which catches a stale `dist` bundle.
   - If a worker can't be constructed, every queued task is rejected and removed.
4. **Catch audit, done mechanically.**
   - 285 catch sites scanned, 120 of them reachable from git/gh, each with a recorded verdict.
   - 10 sites get an explicit rethrow. These are the ones where a swallowed failure gets cached, saved to the database, or gates a deletion.
   - Everywhere else, a per-request failure context fails the whole request loudly and refuses any later git write in it. That covers the `renameBranch` and `setBaseBranch` cases.
   - The PR runtime gets two write guards.
5. **Timeout classes by argument form.**
   - Short reads (30 s), medium reads (120 s), network reads such as `ls-remote` (180 s).
   - Mutations (180 s): `fetch`, config and remote write forms, and any form not on the read list.
   - Every pool timeout is logged.
6. **Child processes and a write fence.**
   - Workers report each child's process ID to the main thread, which kills it on timeout, crash or abrupt exit.
   - A mutation that ends without a clear result blocks further writes to that folder until the process is confirmed gone.
   - Test 6b-5/6 checks whether killing Git's launcher also stops the real git. If it doesn't, the plan switches to calling the real git binary directly.
7. **Output budget.** The worker counts output bytes and rejects oversized results instead of truncating them. The ignored-dirs task now fails loudly inside the worker, and `[]` is returned only by the main-side wrapper for genuine git failures.
8. **Tests that run on Windows.**
   - Main-side logic is tested under bun with an injected pool.
   - Worker behaviour is tested under Node and Electron-as-node against a freshly built test bundle, because the source files can't load under Node directly.
   - No shell-script shims.

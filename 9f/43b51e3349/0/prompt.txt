## 1. Recommended approach

### MUST-1 — port the manifest failover into the embedded Python hook

Env URL first (unchanged fast path), then each `~/.superset/host/*/manifest.json` endpoint, stopping at the first response not containing `"ignored": true`.

Alternatives and why each loses:
- **Queue + retry in the hook** (report's proposal): retrying a permanently dead port never delivers, and a background drain process is the `(HOOK-FORK-DIET)` fork cascade this fork banned.
- **Raise the 1.5 s timeout**: nothing is slow, the port is gone. Pure agent stall, zero delivery.
- **Reduce the SubagentActive flood**: the flooded host has a 0.04% error rate.
- **Marker-driven resync alone**: heals the dot but every other event from those terminals still vanishes.
- **Stable socket / port pinning**: rejected at `plans\agent-hook-url-frozen-port.md:90-91`; reasons hold.

Decisive advantage: `writeNotifyScriptIfChanged()` (`pane-map-hook.ts:2736`) rewrites the script every desktop start and Python re-reads it per fire, so **this heals the 6 already-orphaned live terminals on their next event** with no terminal restart.

`(HOOK-FORK-DIET)` risk: **none.** That footgun is `.sh` templates forking subprocesses under emulated msys2. This is one Python process doing stdlib file reads and in-process `urlopen`.

Cost: fast path unchanged. A dead env URL already costs 1.5 s (3 s when the companion retry fires, `:2623-2642`); drop the per-candidate timeout to **0.75 s** and the worst case halves while actually delivering.

### MUST-2 — make the marker the thing manual clear deletes, and give the renderer the axis clear it never performed

**Host half (authoritative).** New mutation `terminalAgents.dismissWorkspaceStatuses`: per terminal in scope, delete the `<terminalId>.askq` directory, force the binding to `Stop` via the existing `store.clearWorkspaceStatuses`, and settle any pending companion question via `markStale`.

**Renderer half.** `handleClearStatus` awaits that mutation, then calls the already-existing, uncalled `useV2NotificationStore.clearWorkspaceStatuses(workspaceId)` (`store.ts:648-690`) — your name-collision finding.

On sharing one path with the automatic answer-clear: **they cannot be one function**, because they differ on the only axis that matters — manual may drop a live red, automatic may not. What they share, and what removes the duplication that matters, is the **marker mutation and its path derivation**. The `.askq` path is built in three places today: the Python hook (`pane-map-hook.ts:602-629`), the Electron watcher (`agent-jsonl-watcher.ts:505-546`), and the host reader (`agent-status-snapshot.ts:127-138`). A fourth ad-hoc copy is exactly the parallel mechanism to avoid, so the new writer goes **in `agent-status-snapshot.ts`, sharing one path builder and one `SAFE_MARKER_SEGMENT` guard with the reader.** Full unification across Python/main/host needs a rewrite and is out of scope; I am not pretending otherwise.

Host-side rather than Electron main because the marker lives on the machine the agent runs on — for a relay or remote host, main's `homedir()` is the wrong disk. The host also already holds the binding and the companion store, so one round trip does all three.

`markStale` not `resolve`: `resolve` stamps answered-by provenance (`question-store.ts:757-761`) and nobody answered. `markStale` (`:1976-1991`) is terminal, non-provenance-bearing, and still routes through `settle()` → `onSettled` → `push.cancelPending` (`companion\index.ts:663-676`), so the phone notification retracts. Same retraction, honest record.

**Deliberately not deleted: the run-dir subagent markers.** They do not re-assert red on resync — resync replays `lastEventType`, forced to `Stop`. They only shape the *next* hook decision, and a running subagent re-asserting yellow at its next event is correct. Deleting them would corrupt live subagent tracking.

**Cross-window propagation by convergence, not broadcast.** Marker gone plus binding `Stop` means any other window's next resync converges to cleared. I considered broadcasting `Detached` (clears both axes at `statusTransitions.ts:51-62`, chime-exempt at `lifecycleEvents.ts:74-88`) — rejected, because `Detached` also means "session ended" (`map-event-type.ts:11`) and asserting it about a live agent is a lie told to fix a refresh delay.

## 5. Risks and edge cases

**MUST-1**
- Multi-org double delivery impossible — a terminal id lives in one host's `terminal_sessions`; others answer `ignored:true`.
- A stale manifest from a crashed host adds 0.75 s. Manifests are rewritten per start (`apps\desktop\src\main\host-service\index.ts:126-138`), one per org. Do not add a cache for a two-entry loop.
- Predicate drift: if upstream ever returns a body containing literal `"ignored": true` for a delivered event, detection inverts. Covered by tests.
- Ordering: `_deliver` must stay strictly after the marker mutations in `_decide_event_type` (`:2500-2513`) so markers survive total delivery failure.
- `SUPERSET_HOME_DIR` honoured for the manifest glob, **not** for marker paths — the host reads markers at a hardcoded `homedir()` (`agent-status-snapshot.ts:133-138`), so unifying would silently break the resync. Comment it; do not "clean it up".

**MUST-2**
- **Dropping a live red is intended** and is the user's explicit decision. A genuinely blocked agent shows red again at its next hook event; between click and event the dot lies. This is why no automatic path may reuse it.
- Marker delete racing a *new* owner mid-dismiss destroys that question's red. Bounded to milliseconds, self-heals at the next event. Do not add locking.
- Partial failure across N terminals: fail loud on the first marker error and report which succeeded. Silent partial success is what produced this bug class.
- Remote/relay hosts: markers deleted on the **host's** disk — the reason this is not in Electron main.
- Other windows lag until their next resync: ≤60 s with SHOULD-B, until reconnect without it.
- No schema change, no migration, no new persisted key (`partialize` at `store.ts:745-753` already covers the maps).
- Three similarly-named functions (host `clearWorkspaceStatuses`, renderer `clearWorkspaceStatuses`, new `dismissWorkspaceStatuses`) is a real readability hazard — the name collision already caused this bug. Cross-reference all three in comments.

## 4. Risks

- **Duplicate delivery** if a slow live host processes a request we abandoned and the next candidate also accepts. Two identical broadcasts: harmless on the dot axes, and the companion path is already protected — the retry re-sends the *same* `companionLifecycleEventId`, which the sink matches against its applied-id window (`pane-map-hook.ts:2543-2555`). Bounded further by keeping 1.5 s.
- **Foreign server on a recycled port** answering 200 with arbitrary text: rejected by positive envelope parsing. This is the concrete reason the polarity flip matters.
- **All-ignored** on a genuinely wedged pane: one log line per event, no error spam, no retry. Matches notify.sh.
- **Marker fence residual**: a question whose marker write and our `stat` interleave inside one mtime tick. NTFS granularity ~100 ns against a multi-millisecond mutation; not a practical window. A `stat` failure never deletes.
- **Dismissal is still allowed to drop a live red** — the reds that existed at click time. That is the user's explicit decision. The fence narrows it to exactly that set; it is no longer an unbounded race, and I am not claiming it self-heals.
- **`pendingAfter: true`** means a newer question survived the dismissal. The renderer must not present that terminal as cleared; surface it rather than hide it.
- **Total probe budget** could in principle truncate a legitimate multi-org probe. 4 s against two 1.5 s candidates leaves headroom; log on exhaustion.
- **Host-down click**: green clears, red/yellow stay, toast fires. Deliberate, stated above.
- **Three similarly-named functions** (host `clearWorkspaceStatuses`, renderer `clearWorkspaceStatuses`, new `dismissWorkspaceStatuses`). The collision already caused this bug — cross-reference all three in comments.
- No schema change, no migration, no new persisted key (`partialize`, `store.ts:745-753`, already covers the maps).
